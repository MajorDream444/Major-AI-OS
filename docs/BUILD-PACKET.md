# MAIM ecosystem build packet register

8 November 2026 · Draft for review

[Founder-approved learning and commerce architecture](decisions/MAIM_LEARNING_AND_COMMERCE_ARCHITECTURE_2026-11-05.md) governs the roles below. Each software release gets a scoped six-document packet that cites the owning source for each decision. Existing approved artifacts can satisfy a slot by reference.

| Layer | Authority and build packet scope |
| --- | --- |
| MAIM mindset and front door | This repo owns ecosystem meaning, [ABCs Volume 1](curriculum/ABC_VOLUME_1_MINDSET.md) and parent design. Separate the public website, learning pathways and MAIM Foundations Cohort when auditing the actual release scopes. Verify the website's implementation repo and deployment before recording runtime claims. |
| MAIM Academy | [Academy application repo](https://github.com/MajorDream444/MAIMACADEMY) owns delivery, Volume 2, learner experience and fulfillment. [Founding Cohort 01] is the first release packet. [School V1](https://github.com/MajorDream444/MAIMACADEMY/blob/main/docs/school/IMPLEMENTATION-AND-QA.md) has separate review and hosted gates. |
| Spark Lab | Facilitated through Academy. Define a packet per sprint software release, with a specific participant outcome, support limits, acceptance proof and fulfillment owner. MAIM owns the source mindset. |
| Academy brand | [Academy brand repo](https://github.com/MajorDream444/MAIM-Academy---brand) owns Academy visual and verbal application. Approved assets and design decisions are references for the Design Brief. |
| Commerce | [MAIM Commerce Catalog](https://github.com/MajorDream444/MAIM-Commerce-Catalog) owns offers, prices, SKUs, Stripe mappings, entitlements and release evidence. Each software packet references the correct offer. |
| Publishing and library | [ABCs Studio](https://github.com/MajorDream444/MAIM_ABC_STUDIO), [Ten Pillars](https://github.com/MajorDream444/MAIM_10_Pillars), [Major Moves](https://github.com/MajorDream444/major-moves-series) and [Lucky Library](https://github.com/MajorDream444/MAIM-LUCKY-LIBRARY) retain their editorial workflows. Give the software that distributes or delivers their work its own build packet. |
| Production and distribution | Keep media production, channel publishing, and automation under their existing authorities. Verify source and release receipts in the owning systems. Keep restricted operating links in authorized workspaces. |

## Yadi review procedure

For each scoped release, record the owner, repo and exact revision, the six document links, per-slot review status, approvals, open decisions, and the next deliverable. Match each founder requirement to its implementation ticket and observable acceptance evidence. Use the existing approved intake and job process. Record local job acknowledgement separately. A product revision returns affected requirements to review. Build approval and release authorization are separate.
